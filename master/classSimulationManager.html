Detailed Description

State of a restG4 simulation shared by all the threads: the REST objects of the configuration, the queue of events to write, the counters and the stop conditions.

Created once in the master thread. Each worker thread has its own OutputManager (thread_local), which builds the TRestGeant4Event of the current event and submits it to the queue (InsertEvent); WriteEvents writes the queued events in the TRestRun output tree, one thread at a time. The run stops when nEvents are simulated, the requested entries are stored, the time limit is reached or on CTRL-C (StopSimulation).

Volume biasing (biasingVolumes of the metadata): Application runs a Geant4 run (BeamOn) per stage. During stage k (k < number of volumes) the worker threads store the particles entering volume k (StoreBiasingParticle, thread safe); between the runs the master thread sorts them and makes them the particles replayed by stage k + 1 (StartNextBiasingStage), read only during the run: event i replays particle i / biasingFactor. Only the events of the last stage are written.
