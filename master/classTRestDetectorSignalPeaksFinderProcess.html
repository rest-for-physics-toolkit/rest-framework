Detailed Description

Finds all the peaks of the signals of a TRestDetectorSignalEvent and groups them in time coincidence windows. The event is not modified. See the class documentation in TRestDetectorSignalPeaksFinderProcess.cxx (observables and example).

Author
Luis Obis luis..nosp@m.anto.nosp@m.nio.o.nosp@m.bis@.nosp@m.gmail.nosp@m..com
JuanAn García juana.nosp@m.ngp@.nosp@m.uniza.nosp@m.r.es

Finds all the peaks of each signal with TRestPulseShapeAnalysis::GetPeaks and groups the peaks of the event in time coincidence windows. It replaces the legacy TRestRawPeaksFinderProcess: it works on detector signals, whose baseline is already subtracted and whose times are physical, so there is no baseline, time conversion or calibration; and channels are not selected by type, the signals of each detector (e.g. vetoes and Micromegas) are split beforehand with TRestRawSignalChannelSelectionProcess and analysed separately. Legacy veto signals (TRestRawSignal::GetPeaksVeto) used halfWindow 2, maxGreaterEqual 0, refineMaximum false and amplitudeHalfWindow 0. Legacy windows contained the peaks up to window / 2 after the first one.

Observables, the peaks sorted by time and then by signal ID:

  • PeaksSignalID, PeaksTime, PeaksAmplitude, PeaksWindowIndex: one entry per peak.
  • WindowTime (time of the first peak), WindowMultiplicity (number of peaks), WindowAmplitude (sum of the peak amplitudes): one entry per window.
  • NPeaks, NPeaksSignals (signals with at least one peak), NWindows, PeaksAmplitudeSum.

Parameters: threshold (100), distance (2 us), halfWindow (5), maxGreaterEqual (3), refineMaximum (true), amplitudeHalfWindow (1), window (1 us).

Example:

peaksFinder: class: "TRestDetectorSignalPeaksFinderProcess" threshold: 50 distance: 400ns window: 200ns
