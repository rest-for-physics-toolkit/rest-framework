Detailed Description

Pipeline of dataset processes (TRestDataSetProcess): opens a dataset, each process obtains its parameters and adds its columns, in order, and the processed dataset is written once. See the class documentation in TRestDataSetProcessManager.cxx.

manager:
class: TRestManager
dataSetProcessing:
class: TRestDataSetProcessManager
inputFileName: "Dataset_Background.root" # restManager --i
inputFormat: "Dataset_[runTag].root" # optional, [tag] values for outputFileName
outputFileName: "D_[runRange]_[runTag]_Calibrated.root" # restManager --o
calib:
class: TRestDataSetCalibration
referenceFileName: "Dataset_Calibration.root"
...
Author
JuanAn García juana.nosp@m.ngp@.nosp@m.uniza.nosp@m.r.es

Pipeline of dataset processes, a section of TRestManager (instead of TRestRun and TRestEventProcessManager) run by restManager: the dataset inputFileName is opened, each process (TRestDataSetProcess: TRestDataSetCalibration, TRestDataSetGainMap, TRestDataSetLogOdds...), in order, obtains its parameters (from its referenceFileName, see TRestDataSetProcess) and adds its columns, and the processed dataset is written once in outputFileName. The processes can use the columns of the previous ones (e.g. a log odds with the calibrated energy), in the dataset processed; their reference is used as it is.

The output dataset has all the columns of the input and the new ones, the runs of the input, and in RESTMetadataStore the metadata of the input (its TRestDataSet, with this output, and the dataset processes applied before), this pipeline, each process with its results and the TRestCut used by them. The objects of each process (spectra, fits, PDFs) are in RESTDataSetStore/<class>/<name>; those of the processes of the input are kept. A process with the name of one of the input replaces it, with a warning, if it has the same class (otherwise it is an error: the configurations are stored by name).

Parameters

  • inputFileName: the dataset processed (generated with REST_GenerateDataSet, or processed before); restManager --i. With a TRestDataSet section in the same manager it is not used: the dataset is generated and processed in memory and only the processed one is written (the generated one too if the TRestDataSet has an outputFileName); its processes with an empty referenceFileName compute their parameters on it.
  • outputFileName: the dataset written; restManager --o. As the outputFileName of TRestRun, with [key]: a tag of inputFormat, otherwise a key of the runs of the input dataset (TRestDataSet:: ResolveFilePattern: [runStart], [runEnd], [runRange], or a parameter of the runs, [runTag], [runInfo.key]..., if it is the same in all of them, or [key|default]), e.g. "D_[runStart]_[runEnd]_[runTag|Mixed]_Calibrated.root".
  • inputFormat: pattern of the name of the input dataset with [tag] (e.g. "Dataset_[runTag].root", each tag a part without "_"), as the inputFormat of TRestRun; the values of the tags are those of outputFileName, so the same configuration processes several datasets with only –i. An input name that does not match it is an error.
  • the processes, as sections (name: {class: ..., ...}), in order.

The TRestAnalysisPlot of the manager without inputFileName draw the output dataset.

Example:

manager: class: "TRestManager"

energy: class: "TRestCut" conditions: range: "calib_Energy > 4 && calib_Energy < 8"

dataSetProcessing: class: "TRestDataSetProcessManager" inputFileName: "Dataset_Background.root" outputFileName: "Dataset_Background_Processed.root"

calib: class: "TRestDataSetCalibration" referenceFileName: "Dataset_Calibration.root" observable: "trackAnalysis_MaxTrackEnergy" range: [0, 20000] peaks:

  • {energy: "5.9 keV"}

odds: class: "TRestDataSetLogOdds" referenceFileName: "Dataset_Calibration_Processed.root" # with calib_Energy cuts: ["energy"] observables:

  • {observable: "trackAnalysis_MaxTrack_XYZ_SigmaZ2", range: [0, 20]}

New class (legacy: each class read and wrote its own dataset).
