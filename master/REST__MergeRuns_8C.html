int REST_MergeRuns ( const std::string &  filePattern,
const std::string &  outputFile 
)

Merges the subruns of a run in a single run file: the files of filePattern (TRestTools:: GetFilesMatchingPattern) must have the same runNumber, consecutive subRunNumber (also files already merged, by their mergedSubRuns), the same event trees and analysis tree (branches and types) and the same processing (all their metadata but the TRestRun equal). The trees are merged as the threads of TRestManager (TFileMerger), in subrun order; the other objects (readouts, geometry) are copied from the first subrun. The TRestRun of the merged file is the one of the first subrun with subRunNumber the first one, mergedSubRuns all of them, startTime the earliest, endTime the latest, entriesSaved and exposureTime the sums and outputFileName the merged file; its codeVersion, codeCommit and codeClean are those of the first subrun (the code that wrote the data, not the one merging it).

Simulations (files with a TRestGeant4Metadata, restG4 outputs or their analysis) of the same configuration with different seeds (e.g. restG4 –seed in parallel jobs) are merged as a single simulation: their run number and subrun do not matter (the TRestRun is the one of the first file, without mergedSubRuns); the TRestGeant4Metadata may differ only in seed, nEvents, nRequestedEntries and the showersUsed and exposureTime of the cry generator, which are added up (the seed is the one of the first file), and a seed repeated is an error (the same events). The files are merged in the order of the pattern and the eventID of each one is shifted by the events simulated in the previous ones, so all the events have different IDs (as REST_Geant4_MergeRestG4Files of legacy).

Parameters
filePatternPattern of the input run files (at least two files must match).
outputFileMerged output file (must not be one of the inputs); it is recreated.
Returns
0 on success, 1 on error (the reason is printed).
