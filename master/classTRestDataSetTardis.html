Detailed Description

Dataset process that adds the time since the previous event in chronological order, across all the runs of the dataset (<name>_timeDelay, in seconds); optionally the previous event in the same channels of the readout (channels). See TRestDataSetTardis.cxx.

Author
JuanAn García juana.nosp@m.ngp@.nosp@m.uniza.nosp@m.r.es

Adds <name>_timeDelay: the time in seconds since the previous entry of the dataset in chronological order (timeSeconds and timeNanoSecs), across all the runs; NaN for the first entry. Both timestamp columns are needed (datasets generated without timeNanoSecs must be generated again). The seconds and the nanoseconds are subtracted apart, so the delay keeps the nanosecond precision.

With channels, the delay is the time since the previous entry in the same place of the readout, e.g. to find the events correlated in space and time (a decay after an activation, the afterpulses of a spark). The channels are the physical IDs of the readout (after the decoding, not the DAQ channels) of each event, a vector column, e.g. "rawToSignal_SignalsPhysicalID" (see TRestRawToDetectorSignalProcess). Optionally only the channels over a threshold: channelObservable, a vector column with a value per channel (same size and order as channels), and channelThreshold. The readout (readout) is the one of the TRestDetectorReadoutManager of the dataset; it gives:

  • the neighbours of each channel (TRestDetectorReadout::GetAdjacentChannels: physical ID - 1 and + 1, without crossing between the X and Y strips of a Micromegas or between rows of fibres);
  • the groups of channels: those measuring the same coordinates (the finite coordinates of GetPositionFromChannel), e.g. the X strips and the Y strips, the families of fibres along each axis; a pixel readout has a single group.

Two entries are in the same place if they have a group in common and, in each group they both have, channels within channelTolerance neighbours (0: the same channel). E.g. with strips, the previous event with an X strip next to one of the X strips of the event and a Y strip next to one of its Y strips; an event without Y strips (below threshold) only needs the X strips. Entries without any channel of the readout get NaN. Events of a single readout are expected (e.g. after the cuts of a detector): the channels that are not in the readout are ignored.

The dataset is not reordered: each entry keeps its place and gets its delay. The timestamps (and the channels) are read in memory (an event loop when the process is applied) and matched to the entries by runIndex, eventID and subEventID, as TRestDataSetCombine. Entries with the same timestamp are ordered by runIndex, eventID and subEventID: the first of them has the delay from the previous timestamp, the others 0.

Parameters:

  • channels: column or expression of the physical channels of each event; empty (default): no place, the previous event wherever it is.
  • readout: instance name of the readout in the TRestDetectorReadoutManager of the dataset; empty: its data readout (only with channels).
  • channelTolerance: number of neighbours of a channel in the same place (1).
  • previousObservable, previousThreshold: only the events whose previousObservable (a value per event, e.g. trackAnalysis_TotalEnergy) is over previousThreshold can be the previous event: the delay is the time since the last of them (in the same place with channels), e.g. the time since the last high energy event. The others get their delay as any event but are never the previous one. Empty previousObservable (default): any event.
  • channelObservable, channelThreshold: the channels whose value of channelObservable is not over channelThreshold are not used (empty channelObservable: all the channels), e.g. the noise of single channels.
  • cuts: names of the TRestCut of the manager, e.g. to remove the noise. The entries that do not pass them are removed from the dataset before the delays are computed: a noise event is never the previous one. The noise of single channels is removed with channelObservable and channelThreshold.
  • referenceFileName, referenceSelection: not used (a warning). The process has no parameters.

The delays are those of the entries at this point of the pipeline: later filters (cuts, other processes) do not recompute them.

tardis:
class: "TRestDataSetTardis"
cuts: ["noise"] # optional: removes the noise events
channels: "rawToSignal_SignalsPhysicalID" # optional: the previous event in the same place
channelTolerance: 1
previousObservable: "trackAnalysis_TotalEnergy" # optional: the previous event over
previousThreshold: 5000 # previousThreshold
channelObservable: "rawToSignal_SignalsMaxAmplitude" # optional: only the channels over
channelThreshold: 25 # channelThreshold
