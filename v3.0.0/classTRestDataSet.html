Detailed Description

Selection of the analysis trees of several runs (or of several datasets, merged) in a single tree, with the description of each run (TRestRunInfo): every entry has the index of its run (runIndex), so the information of the runs is never lost or summarized. See the class documentation in TRestDataSet.cxx for the details of every parameter and of the dataset file.

Configuration keys (inputFileName opens an existing dataset instead of generating one):

dataSet:
class: TRestDataSet
filePattern: "R*_LINEAR.root"
observables: ["trackLineAnalysis_*"]
runConditions:
mesh: "runInfo.meshVoltage > 300 V"
dates: 'startTime > date("2022/04/28") && endTime < date("2022/11/25 13:20")'
cuts: ["fiducial"]
columns:
energyPerVolt: "trackLineAnalysis_Energy / runInfo.meshVoltage"
outputFileName: "D_[runStart]_[runEnd]_[runTag|Mixed].root"
Author
Javier Galán javie.nosp@m.r.ga.nosp@m.lan.l.nosp@m.acar.nosp@m.ra@ce.nosp@m.rn.c.nosp@m.h
JuanAn García juana.nosp@m.ngp@.nosp@m.uniza.nosp@m.r.es

Selection of the analysis trees of several runs in a single tree, together with the description of each run (TRestRunInfo: numbers, tags, runInfo, times, entries; not the processing of its TRestRun). Every entry has the index of its run (column runIndex, position in the list of runs), so any parameter of the run of an entry (run number, tag, runInfo, start and end times...) is known and the information of the runs is never summarized: totals (e.g. the run time) are computed from the runs when they are needed, also after merging datasets.

It is generated with the macro REST_GenerateDataSet (no TRestRun nor TRestManager needed):

restRoot REST_GenerateDataSet("dataset.yaml", "dataSet")

or with restManager, as a section of the TRestManager with the TRestCut it uses (no TRestRun): –i is its filePattern and –o its outputFileName; with a TRestDataSetProcessManager in the same manager, the dataset generated is processed by it in memory (–o is then the output of the pipeline) and only the processed dataset is written, unless the TRestDataSet has an outputFileName:

restManager –c dataset.yaml –i "R*_ANA.root"

The inputs (filePattern) are either run files (output of restManager) or datasets: their runs are joined and runIndex renumbered, the result is a dataset like any other. A run cannot be twice (same runNumber and subRunNumber, also one of the mergedSubRuns of a run merged with REST_MergeRuns, or, for runs without number, the same file): it is an error. A TRestAnalysisPlot takes a dataset file as input as it takes a run file (its inputFileName, or restManager --i). From restRoot: Generate(cuts), GetDataFrame(), Define(name, expression), Write(fileName); a dataset file is opened as it is with the constructor TRestDataSet(fileName), e.g. as _dataSet by restRoot Dataset.root (REST_OpenInputFile, REST_OpenDataSet). Each run is a TRestRunInfo built from the TRestRun stored in its file (GetRuns()[i].run, no file opened); PrintDataSetInfo() prints a summary with a line per run, PrintAllMetadata() also the configurations and every run.

The metadata of the files are read directly (TRestYAMLUtils::ReadMetadataStore), no TRestRun is opened.

Parameters

  • filePattern: the files the dataset is generated from (TRestTools::GetFilesMatchingPattern, * and ? in the file name, e.g. "data/R000*_Calibration_*.root", or datasets to merge, "Dataset_*.root").
  • inputFileName: a dataset already generated, opened as it is; its stored configuration is kept apart, not changed. Not for the generation.
  • observables: patterns (* and ?) of the analysis tree columns written, e.g. ["trackLineAnalysis_*", "rawAnalysis_NumberOfSignals"]. Empty (default): all. eventID, subEventID, timeSeconds, timeNanoSecs (if available) and runIndex are always written.
  • runConditions: name: expression (as the conditions of TRestCut) on the parameters of each run (TRestRunInfo), as written in its YAML: runNumber, subRunNumber, runTag, runType, runUser, experimentName, startTime, endTime (Unix time), entriesSaved, runInfo.key... A number (also with units, e.g. runInfo.meshVoltage: 300 V, in REST units) is compared as a number (a literal with units, e.g. runInfo.meshVoltage > 300 V, is also converted to REST units), a text as a std::string (e.g. runTag == "Calibration"), a date with date("YYYY/MM/DD HH:MM") (local time; also YYYY-MM-DD, with or without HH:MM or HH:MM:SS), e.g. startTime > date("2022/04/28 00:00"). A run is selected if it fulfills all of them; a parameter used must be in all the runs.
  • cuts: names of the TRestCut applied to the entries (sections of the same YAML).
  • columns: name: expression of new columns, in order (a column can use the previous ones), with observables and run parameters (the value of the run of each entry), e.g. gainCorrected: "rawAnalysis_ThresholdIntegral / runInfo.gain".
  • outputFileName: the file written (Write; by the macro if it is not given to it), with [key] of its runs (ResolveFilePattern): [runStart], [runEnd], [runRange] (00010_00012, or 00010 with a single run) and the parameters of the runs that are the same in all of them; [runTag|Mixed] gives Mixed if they are not the same (without default it is an error). E.g. "D_[runStart]_[runEnd]_[runTag|Mixed].root".

Dataset file

  • AnalysisTree: the columns, with runIndex;
  • RESTDataSetInfo: the runs, a TObjString with a YAML list, one element per run in the order of runIndex (its position), with run (its TRestRunInfo), fileName (run file), entries (of the run file), selectedEntries (in the dataset) and processing (index in RESTDataSetProcessing);
  • RESTDataSetProcessing: the different processings of the runs, a TObjString with a YAML list (each one instance -> configuration of the TRestEventProcessManager); datasets merged join their lists;
  • RESTMetadataStore: this TRestDataSet (filePattern: what it was generated from, outputFileName: the file, and codeVersion, codeCommit and codeClean: the code that wrote it, REST_Version) and the TRestCut used; also the metadata of the first input file with runs selected (processing, readouts, TRestGeant4Metadata...), but its TRestRun (each run is in RESTDataSetInfo) and the TRestDataSet it comes from (a dataset as input);
  • Readouts and Geometry: the readouts (TRestDetectorReadout::Export) and the geometry (restG4) of that file, e.g. a TRestDetectorReadoutManager with readouts: [{instanceName: ..., decodingName: ..., inputFileName: "Dataset.root"}] loads a readout of the dataset.

The runs of a dataset must have the same setup, otherwise Generate throws: the processes (each TRestEventProcessManager with the same processes, name and class, in the same order), the branches of the analysis tree (name and type), the readouts (configuration, decodings and geometry) and the geometry. The parameters of the processes can differ: each different processing (the configurations of the TRestEventProcessManager, without eventsToProcess, nThreads and verbose) is kept (GetProcessings, GetProcessing(runIndex)) and a warning lists the parameters that differ, with their values and runs. The geometries are compared by their hash (TRestTools:: GetGeometryHash: volumes, with shape, material and capacity, and the name and position of their daughters), written with them (TRestTools::WriteGeometry, by restG4 and the readouts): they are not read, except in files written before the hash. The other metadata (e.g. the seed of a simulation) can be different; those of the first file are written.

Example:

fiducial: class: "TRestCut" conditions: originX: "trackLineAnalysis_OriginX > 20 && trackLineAnalysis_OriginX < 225" dataSet: class: "TRestDataSet" filePattern: "R*_LINEAR.root" observables: ["trackLineAnalysis_*"] runConditions: runNumber: "runNumber > 370 && runNumber < 375" dates: "startTime > date(\"2022/04/28\") && endTime < date(\"2022/11/25 13:20\")" mesh: "runInfo.meshVoltage > 300 V" cuts: ["fiducial"] columns: energyPerVolt: "trackLineAnalysis_Energy / runInfo.meshVoltage" outputFileName: "Dataset_Calibration.root"

Differences with legacy: the runs (their TRestRunInfo) are stored and every entry has its runIndex, instead of the file names and the relevant quantities (quantity, a value per dataset with a strategy); the run filters are expressions (runConditions) instead of filter with contains/greaterThan/lowerThan/ equalsTo, and the date range (startTime, endTime) is a condition with date(...); merging keeps the runs (legacy kept the metadata of the first dataset and removed the quantities); no temporary files (a single Snapshot in Write); only ROOT files (no txt/csv export); processObservables are patterns of observables (e.g. "final_*"); the macro REST_GenerateDataSets is REST_GenerateDataSet.
