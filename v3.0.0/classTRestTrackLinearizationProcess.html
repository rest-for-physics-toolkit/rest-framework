Detailed Description

Reduces each track (any type) to nodes along the line that best fits its hits, e.g. for alpha tracks. The output event holds one track per input track.

Author
JuanAn García juana.nosp@m.ngp@.nosp@m.uniza.nosp@m.r.es

Reduces each track of a TRestTrackEvent, of any type (XZ, YZ, XYZ, ...), to nodes along a line, meant for linear tracks such as alpha tracks:

  1. The hits are fitted to a line: through their energy weighted mean, along the direction of largest spread (energy weighted principal axis, TRestHitsAnalysis::GetLine), in the coordinates the track defines, between the extreme projections of the hits on it.
  2. Equally spaced nodes are placed along the fitted line: maxNodes or, with nodeDistance, one every nodeDistance (length / nodeDistance + 1 nodes, between 2 and maxNodes), so short tracks get less nodes than long ones.
  3. Each hit goes to its closest node, which moves to the energy weighted mean of its hits and gets their energy and, as sigma, their energy weighted spread in each coordinate (maxIterations k-means iterations, TRestHitsAnalysis::KMeansClustering). Nodes with no hits are dropped. With fixBoundaries, the first and last nodes stay at the ends of the line, with no hits, no energy and no sigma.

The output event holds one track per input track (parent ID = ID of the input track): the nodes, or the input track as it is if it cannot be linearized: no energy, maxNodes < 2 or hits of different types in the track (the undefined coordinates would mix with the defined ones). The number of tracks not linearized is reported at the end of the processing (and each one in debug).

Parameters

  • maxNodes: number of nodes (default 6), the maximum with nodeDistance.
  • nodeDistance: distance between nodes, 0 (default) for always maxNodes.
  • maxIterations: k-means iterations (default 1, as legacy). More iterations move the nodes closer to the hits, with less influence of the fitted line.
  • fixBoundaries: fix the first and last nodes at the ends of the line (default false). Adding 2 nodes to maxNodes is recommended: the end nodes are not pulled towards the centre of the track, which gives a more accurate track length, but a worse length resolution.

Example:

trackLinearization: class: "TRestTrackLinearizationProcess" maxNodes: 8 nodeDistance: 2mm maxIterations: 1 fixBoundaries: false

Migrated from the legacy track library (JuanAn Garcia, 2022). Differences: any track type (legacy only XZ, YZ and XY, the others were kept as they were); the line is the principal axis, which minimizes the distances to it, instead of a fit of one coordinate against the other in both orientations keeping the smallest chi2 (legacy repeated each hit in a TGraph in proportion to its energy), similar for linear tracks; nodeDistance, maxIterations and the node sigmas are new; the output event holds only the tracks of this stage (no levels).
