Detailed Description

Loads and owns a set of detector readouts imported from a ROOT geometry container.

All the readouts are loaded (e.g. to view an event in the whole detector), but the data of a file are those of a single readout, readout (e.g. "micromegas" or "veto"; the detectors are split by TRestGeant4ToDetectorHitsProcess volumes in simulations and by TRestRawSignalChannelSelectionProcess in acquired data). The processes (and TRestDataSetGainMap) use it unless they give their own readout (SelectReadout).

Parameters:

  • readout: instance name of the readout of the data; empty: the only readout loaded.
  • readouts: list of readouts to import (TRestReadoutInfo): instanceName, decodingName (the name given to TRestDetectorReadout::Export) and inputFileName (the ROOT file written by Export, or kSelfFile; it can be a URL, downloaded and cached with TRestTools::GetLocalFile, e.g. a versioned readout of rest-common).

The readouts are imported when the manager gets its run (SetRunInfo) or is read from a file (LoadFromFile). When the manager is written to an output file (WriteMetadata), the imported readouts are stored in it, so the output file is self-contained: only the data readout if readout is given (the others are not stored, nor listed in the stored readouts), all of them otherwise. A dataset of the file keeps that readout only, e.g. one plane of TREX-DM.

readouts: class: "TRestDetectorReadoutManager" readout: "micromegas" # empty: the only readout loaded readouts:

  • {instanceName: "micromegas", decodingName: "iaxo_d1_iaxolab", inputFileName: "readout.root"}
  • {instanceName: "veto", decodingName: "veto", inputFileName: "veto_readout.root"}
