Detailed Description

Run-level container for metadata and ROOT I/O orchestration.

TRestRun owns input/output ROOT files, event trees, event object bindings, and run descriptors used during processing and AOD persistence. The description of the run (numbers, tags, runInfo, times) is its base TRestRunInfo.

Configuration (a section inside the TRestManager of restManager), with the keys of TRestRunInfo plus the processing ones:

run:
class: TRestRun
name: restRun
runNumber: 1 # "auto": a new run number ($REST_HOME/.rest/runNumber)
subRunNumber: 0
runType: Test
runTag: SignalPeaks
runDescription: SignalPeaks
experimentName: Test
runInfo: {meshVoltage: 300 V}
inputFileName: SignalPeaks_input.root
# [parameter] of the name of the input file, used for the run parameters not given
inputFormat: "R[runNumber]_[runTag]_V[runInfo.meshVoltage].root"
inheritInputRun: false # true: the parameters not given are taken from the run of the input file
mainDataPath: /data/rest # prefix of relative output file names
outputFileName: "R[runNumber]_[runTag].root" # "/dev/null" (default): nothing written
outputBasketSize: 1048576 # bytes per branch basket of the output event trees, 0: ROOT default
# outputEvent is written by REST: the last saved event type; codeVersion, codeCommit and codeClean the
# code that wrote the file (REST_Version)

The run parameters not given in the configuration are taken from the name of the input file (inputFormat), otherwise from the run of the input file if inheritInputRun is true; startTime, endTime, mergedSubRuns and runInfo always come from the input run (the keys of the configuration replace those of runInfo). Input files that are not REST run files (e.g. DAQ files) are not opened: they are read by a process. A pattern with wildcards (*, ?) is not opened either (used by TRestAnalysisPlot).

A REST run file contains the AnalysisTree (event info and observables), one tree per saved event type (named as the event class) and the RESTMetadataStore directory with the configurations.
