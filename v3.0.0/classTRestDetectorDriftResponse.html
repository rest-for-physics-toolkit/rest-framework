Detailed Description

Drift of the electrons in a non-uniform field (e.g. a CST field map) as a response per start point: the configuration of its computation (the drift key of a TRestDetectorTransportManager, computed by restGarfield with Garfield++) and the response, written to and read from its own file without Garfield++, used by TRestDetectorHitsDriftResponseProcess.

The parameters (YAML keys), the file format and the use of the response are described in the class documentation (TRestDetectorDriftResponse.cxx).

Author
JuanAn García juana.nosp@m.ngp@.nosp@m.uniza.nosp@m.r.es

Drift of the electrons in a non-uniform electric field (a field map exported from CST Studio Suite) as a response per start point, for special simulations; the drift in a uniform field (the driftField of the medium) is TRestDetectorHitsDriftProcess.

restGarfield computes it (the drift key of a TRestDetectorTransportManager, after the transport and gain tables): it loads the field map in Garfield++ (ComponentGrid), builds the Garfield gas from a transport table of the medium file (without Magboltz) and drifts electrons primary electrons (AvalancheMC, steps of stepSize, with diffusion and attachment) from each node of a regular grid of start points in the detector frame (xRange, yRange, zRange, gridNodes). The drift ends at the boundary plane, at the distance boundary from the readout (TRestDetectorReadout::GetDistanceToReadout), above the mesh, where the amplification starts; the drift region is cut there (the normal of the readout must be along an axis). An electron reaches the boundary if it ends on that plane; ending elsewhere (cathode, walls, out of the map) or attached, it is lost. Each electron drifts independently, so the arrivals from a point depend only on the field and the gas: the response replaces the drift of every electron of every event, up to the spacing of the grid.

Response of each node: the number of primary electrons and of those that arrive, and the histograms of the arrival position, the displacement (u, v) from the node projected on the boundary plane along the axes of the readout plane (PlaneAxes; e.g. normal +z: u = x, v = y), positionBins x positionBins over the range of the arrivals of the node, and of the drift time (timeBins). TRestDetectorHitsDriftResponseProcess uses it for each electron of a hit: it survives with the fraction arrived / primaries interpolated between the 8 neighbouring nodes (GetSurvival), and its displacement and time are sampled from one of those nodes, chosen with its interpolation weight times its survival (SampleArrival); the displacement is added to the hit projected on the readout, exact for a uniform field.

Parameters (drift key): fieldMap, fieldMapOffset ([0, 0, 0] mm), readouts (YAML file with the TRestDetectorReadoutManager), readout (empty: its data readout), boundary (0 mm), transportTable (key of the table of the medium file; empty: the only one), xRange, yRange, zRange (mm), gridNodes ([2, 2, 2], at least 2 per axis), electrons (1000), stepSize (1 mm), positionBins (20), timeBins (20), responseFile and overwrite (false: an existing responseFile is not computed again). The pressure and temperature are those of the medium. The time of the computation grows with the nodes, the electrons and the drift length over stepSize.

drift: fieldMap: "drift_field.txt" fieldMapOffset: [0 mm, 0 mm, 0 mm] readouts: "readouts.yaml" boundary: 0.5 mm xRange: [-100 mm, 100 mm] yRange: [-100 mm, 100 mm] zRange: [0 mm, 190 mm] gridNodes: [21, 21, 20] electrons: 1000 responseFile: "drift_response.root"

Response file: the metadata DriftResponse in RESTMetadataStore (YAML: configuration, the drift keys; medium, pressure, temperature, transportTable, positionBins, timeBins and generator, the program, date and code that computed it) and the tree DriftResponse, an entry per node (x fastest, then y, then z) with primaries, arrived, range (u min, u max, v min, v max, t min, t max; mm and us), positionCounts (u bin + positionBins * v bin) and timeCounts.
